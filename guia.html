1¿Qué es el DNS?

Los equipos de una red se comunican por su dirección IP (por ejemplo, 10.10.0.10), pero a las personas nos resulta más fácil recordar nombres (www.smx.lan). El DNS (Domain Name System, sistema de nombres de dominio) es el servicio que traduce nombres a direcciones IP y direcciones IP a nombres.

  • Trabaja en la capa de aplicación y usa el puerto 53: UDP para las consultas normales y TCP para respuestas grandes y transferencias de zona.
  • Es una base de datos distribuida: ningún servidor lo sabe todo; cada uno se encarga de su parte y sabe a quién preguntar por el resto.
  • Es jerárquico: los nombres forman un árbol que empieza en la raíz.
Es como la agenda del móvil: buscas «Marta» y el móvil marca su número sin que tengas que sabértelo.

2El árbol de nombres

Los nombres DNS se leen de derecha a izquierda, del nivel más general al más concreto. Cada parte separada por un punto es una etiqueta.

ns1 · srv1 · pc01 · wwwequipos (hosts)
  • Raíz (.): la cima del árbol. La sirven 13 grupos de servidores raíz repartidos por el mundo.
  • TLD (Top Level Domain, dominio de primer nivel): .com, .org, .es, .cat… En el laboratorio usamos .lan, que no existe en internet y solo vale dentro de nuestra red.
  • Dominio y subdominio: smx.lan es un dominio dentro de lan; aula1.smx.lan sería un subdominio de smx.lan.
  • Host: el nombre de un equipo concreto, como pc01.

FQDN: el nombre completo

Un FQDN (Fully Qualified Domain Name) es el nombre completo de un equipo, desde el host hasta la raíz:

pc01host.smxdominio.lanTLD.raíz
El punto final importa. En los archivos de zona, pc01.smx.lan. (con punto) es un nombre completo. Sin el punto, BIND le añade el dominio detrás y queda pc01.smx.lan.smx.lan., que no existe. Los nombres cortos (pc01) se escriben sin punto y BIND los completa solo.

3Zonas

Una zona es la parte del árbol de nombres de la que se encarga un servidor DNS. Se guarda en un archivo de zona con todos sus registros. Dominio y zona no son lo mismo: el dominio es el nombre (smx.lan); la zona es la parte que administra un servidor concreto (puede delegar subdominios en otros servidores).

Zona directa

Traduce nombre → IP. Se llama como el dominio: smx.lan. Contiene registros A, AAAA, CNAME, MX…

Zona inversa

Traduce IP → nombre. Contiene registros PTR. Su nombre es la parte de red de la IP al revés + .in-addr.arpa.

Cómo se nombra la zona inversa

Para la red 10.10.0.0/24 se toman los tres primeros octetos (la parte de red), se invierten y se añade in-addr.arpa:

10.10.0  →  0.10.10  →  0.10.10.in-addr.arpa

; dentro de la zona solo se escribe el último octeto (la parte de host)
101   IN   PTR   pc01.smx.lan.     ; 10.10.0.101 → pc01.smx.lan

Se escribe al revés porque en el DNS lo general va a la derecha: en una IP lo general (la red) va a la izquierda.

Servidor maestro y esclavo

  • Maestro (primario, type master): tiene el archivo original de la zona; los cambios se hacen aquí.
  • Esclavo (secundario, type slave): guarda una copia que pide al maestro mediante una transferencia de zona (AXFR). Si el maestro cae, el esclavo sigue respondiendo. En la práctica, pc02 hace de secundario.
  • El esclavo solo copia la zona si el número de serie del SOA del maestro es mayor que el suyo. Por eso hay que subir el serial en cada cambio.

4Registros (RR)

Cada línea de un archivo de zona es un registro de recurso (Resource Record). Todos siguen el mismo formato:

nombre   [TTL]   clase   tipo   dato
pc01              IN      A       10.10.0.101
  • nombre: a qué se refiere. @ significa «el propio dominio» (smx.lan.).
  • TTL (opcional): segundos que otros servidores pueden guardar la respuesta en caché.
  • clase: casi siempre IN (Internet).
  • tipo y dato: qué clase de información es y su valor.
TipoPara qué sirveEjemplo en smx.lan
SOAStart Of Authority. Primer registro de toda zona: servidor principal, correo del responsable, número de serie y tiempos.@ IN SOA ns1.smx.lan. admin.smx.lan. (…)
NSName Server. Qué servidores DNS tienen autoridad sobre la zona. Apunta a un nombre, nunca a una IP.@ IN NS ns1.smx.lan.
AAddress. Nombre → dirección IPv4. El más usado.pc01 IN A 10.10.0.101
AAAAIgual que A pero para direcciones IPv6.pc01 IN AAAA fd00::101
CNAMECanonical Name. Alias: otro nombre para un equipo que ya tiene registro A.www IN CNAME ns1
MXMail eXchanger. Servidor que recibe el correo del dominio, con una prioridad: el número más bajo es el preferido.@ IN MX 10 srv1.smx.lan.
PTRPointer. IP → nombre. Solo en zonas inversas.101 IN PTR pc01.smx.lan.
TXTTexto libre. Se usa para verificar dominios y para el correo (SPF, DKIM).@ IN TXT "v=spf1 mx -all"
SRVService. Dónde está un servicio concreto (prioridad, peso, puerto y equipo). Lo usa, por ejemplo, Active Directory._ldap._tcp IN SRV 0 0 389 srv1
Reglas que dan error si no se cumplen:
  • Un nombre con CNAME no puede tener ningún otro registro.
  • NS y MX deben apuntar a un nombre con registro A, nunca a un alias (CNAME) ni a una IP.
  • Toda zona necesita un SOA y al menos un NS, y ese NS necesita su registro A.

5El SOA por dentro

$TTL 604800                      ; TTL por defecto de la zona (1 semana)
@   IN   SOA   ns1.smx.lan.  admin.smx.lan. (
               2026102001   ; Serial  → AAAAMMDDnn: fecha + nº de cambio del día
               604800       ; Refresh → cada cuánto el esclavo mira si hay cambios
               86400        ; Retry   → si falla, cuándo vuelve a intentarlo
               2419200      ; Expire  → cuándo deja de responder si no contacta con el maestro
               604800 )     ; Negative TTL → tiempo en caché de un «no existe»
  • ns1.smx.lan.: el servidor primario de la zona.
  • admin.smx.lan.: el correo del responsable, con un punto en lugar de la arroba (admin@smx.lan).
  • Serial: súbelo cada vez que cambies la zona. Si no, los secundarios y las cachés no se enteran del cambio. El formato fecha + contador (2026102001, 2026102002…) evita equivocarse.
  • Los tiempos van en segundos: 86400 s = 1 día; 604800 s = 1 semana.

6Cómo se resuelve un nombre

Cuando pc01 quiere visitar www.xtec.cat, ocurre esto:

  1. El resolver de pc01 (la parte del sistema que hace preguntas DNS) mira primero su caché y el archivo hosts. Si no lo sabe, pregunta a su servidor DNS (ns1). Es una consulta recursiva: «dame la respuesta final».
  2. ns1 mira si es autoritativo para ese nombre (si lo tiene en sus zonas) o si lo tiene en caché. Como xtec.cat no es suyo, sale a buscarlo.
  3. Pregunta a un servidor raíz: «¿quién lleva .cat?». La raíz no sabe la respuesta, pero le indica los servidores de .cat. Son consultas iterativas: cada servidor responde con lo que sabe o con a quién preguntar.
  4. Pregunta a los servidores de .cat: «¿quién lleva xtec.cat?». Le dan los NS de xtec.cat.
  5. Pregunta al servidor autoritativo de xtec.cat, que responde con el registro A de www.
  6. ns1 guarda la respuesta en caché durante su TTL y se la da a pc01. La próxima vez que alguien lo pregunte, responderá al momento.
Si ns1 está configurado con reenviadores (forwarders), como 8.8.8.8, no hace los pasos 3 a 5: pasa la pregunta al reenviador y espera la respuesta. Es lo que ves en «Monta tu DNS» cuando preguntas por un nombre de internet.

Consulta recursiva

El cliente pide la respuesta completa y el servidor hace todo el trabajo.

Consulta iterativa

El servidor contesta lo que sabe o remite a otro servidor más cercano a la respuesta.

Respuesta autoritativa

Viene del servidor que tiene la zona (flag aa en dig). Una respuesta de caché no lo es.

7Tipos de servidor DNS

Autoritativo

Tiene zonas propias y responde por ellas con autoridad. Puede ser maestro o esclavo.

Solo caché (recursivo)

No tiene zonas: busca las respuestas por los clientes y las guarda en caché para ir más rápido.

Reenviador

Pasa las consultas que no sabe a otro servidor (el del proveedor, 8.8.8.8, 1.1.1.1…).

El ns1 del laboratorio hace las tres cosas: es maestro de smx.lan y de su zona inversa, y reenvía y guarda en caché todo lo demás.

8BIND9 en Ubuntu

BIND9 es el servidor DNS más usado en Linux. Se instala con sudo apt install bind9 bind9utils y su configuración está en /etc/bind/.

ArchivoQué contiene
named.confArchivo principal. Solo incluye los otros tres.
named.conf.optionsOpciones generales: reenviadores, quién puede consultar, recursión.
named.conf.localNuestras zonas: nombre, tipo (master/slave) y archivo.
db.smx.lanArchivo de la zona directa.
db.10.10.0Archivo de la zona inversa.

named.conf.options

options {
    directory "/var/cache/bind";
    forwarders { 8.8.8.8; 1.1.1.1; };    // a quién preguntar lo que no es nuestro
    allow-query { localhost; 10.10.0.0/24; };
    recursion yes;
    listen-on { any; };
};

named.conf.local

zone "smx.lan" {
    type master;
    file "/etc/bind/db.smx.lan";
    allow-transfer { 10.10.0.102; };      // IP del secundario
};

zone "0.10.10.in-addr.arpa" {
    type master;
    file "/etc/bind/db.10.10.0";
};

Zona directa · /etc/bind/db.smx.lan

$TTL 604800
@        IN   SOA    ns1.smx.lan. admin.smx.lan. (
                     2026102001 604800 86400 2419200 604800 )
@        IN   NS     ns1.smx.lan.
@        IN   MX     10 srv1.smx.lan.

ns1      IN   A      10.10.0.10
srv1     IN   A      10.10.0.11
pc01     IN   A      10.10.0.101

www      IN   CNAME  ns1
correo   IN   CNAME  srv1

Zona inversa · /etc/bind/db.10.10.0

$TTL 604800
@        IN   SOA    ns1.smx.lan. admin.smx.lan. (
                     2026102001 604800 86400 2419200 604800 )
@        IN   NS     ns1.smx.lan.

10       IN   PTR    ns1.smx.lan.
11       IN   PTR    srv1.smx.lan.
101      IN   PTR    pc01.smx.lan.
En la zona inversa los nombres de la derecha van siempre completos y con punto final: si escribieras pc01, BIND lo completaría con 0.10.10.in-addr.arpa.

El cliente

Para que un equipo use nuestro DNS, su servidor DNS debe ser 10.10.0.10. En Ubuntu se indica en Netplan (nameservers: addresses: [10.10.0.10], search: [smx.lan]) y se comprueba con resolvectl status. En Windows, en las propiedades IPv4 del adaptador o con ipconfig /all.

9Comprobar y consultar

Antes de reiniciar: revisar la sintaxis

sudo named-checkconf                                  # sin salida = todo bien
sudo named-checkzone smx.lan /etc/bind/db.smx.lan
sudo named-checkzone 0.10.10.in-addr.arpa /etc/bind/db.10.10.0
sudo systemctl restart bind9        # o: sudo rndc reload
sudo systemctl status bind9

Consultas

OrdenQué hace
dig pc01.smx.lanPregunta el registro A. Mira la ANSWER SECTION y el flag aa.
dig smx.lan MXPregunta un tipo concreto (MX, NS, SOA, TXT…).
dig -x 10.10.0.101Búsqueda inversa (PTR).
dig @10.10.0.10 www.smx.lanPregunta a un servidor concreto.
dig +short www.smx.lanSolo la respuesta, sin detalles.
dig @10.10.0.10 smx.lan AXFRPide la zona entera (solo si allow-transfer lo permite).
nslookup www.smx.lanConsulta sencilla; existe también en Windows.
host 10.10.0.10Respuesta en una línea, directa o inversa.
sudo journalctl -u namedRegistro del servicio: aquí salen los errores de carga de zonas.

Respuestas de dig que hay que saber leer

  • status: NOERROR: la consulta ha ido bien (aunque puede venir sin respuesta si ese tipo de registro no existe).
  • status: NXDOMAIN: el nombre no existe en la zona.
  • status: SERVFAIL: el servidor ha fallado; casi siempre la zona no ha cargado por un error de sintaxis.
  • status: REFUSED: el servidor no acepta consultas de ese cliente (allow-query).

11Glosario

DNS
Sistema de nombres de dominio: traduce nombres a IP y al revés.
FQDN
Nombre completo de un equipo, terminado en punto: pc01.smx.lan.
TLD
Dominio de primer nivel: .com, .es, .lan…
Zona
Parte del espacio de nombres que administra un servidor.
Zona directa
Nombre → IP.
Zona inversa
IP → nombre, bajo in-addr.arpa.
RR
Registro de recurso: cada línea de una zona.
TTL
Tiempo, en segundos, que una respuesta puede quedarse en caché.
Serial
Número de versión de la zona, dentro del SOA.
Maestro / esclavo
Servidor con la zona original / con una copia.
AXFR
Transferencia completa de zona del maestro al esclavo.
Resolver
Parte del cliente que hace las preguntas DNS.
Autoritativo
Servidor que tiene la zona y responde por ella.
Forwarder
Servidor al que se reenvían las consultas que no son nuestras.
@
En un archivo de zona, el propio dominio (smx.lan.).
BIND9 / named
El servidor DNS de Linux / el nombre de su proceso.
